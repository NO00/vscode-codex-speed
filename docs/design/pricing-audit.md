# 计费算法核查记录

核查日期：2026-10-27。对象：0.1.10 的离线标准 API 等值费用。结论：六个模型基础单价、百万 token 单位换算及长上下文算式正确；复现并修正了四处边界问题。缓存写入、工具、服务档位和地区附加费用继续不计入当前小计。

## 官方依据

- [标准 API 价格表](https://developers.openai.com/api/docs/pricing)：六模型普通输入、缓存读取、输出单价均与内置表一致；未误取 Fast 或 Flex／Batch 的价格。
- [GPT-6.1 Sol 模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)：单次输入严格超过 272000 时，输入及缓存价乘 2，输出价乘 1.5；该请求整体适用，而非只对超出部分加价。其他内置模型规则逐一核对，见价格设计表。
- [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：总输入包含缓存读取和写入，两者不重叠；普通输入需减去这两项。完整 API 算法还需按 30 分钟／12 小时写入数量分别使用普通输入价的 1.25／2.5 倍，本插件目前明确排除写入金额。
- [Reasoning models](https://developers.openai.com/api/docs/guides/reasoning)：推理 token 已计入输出；不能再叠加一次。

当前三项小计为：`(普通输入 × 输入单价 + 缓存读取 × 缓存单价 + 输出 × 输出单价) / 1000000`。先按单次请求适用上下文规则，再跨模型相加；不逐条舍入。

## 独立金额算例

短请求：总输入 100000，缓存读取 80000，明确写入 0，输出 10000。长请求：总输入 300000，缓存读取 200000，明确写入 0，输出 10000。金额单位为美元。

| 模型 | 短请求 | 长请求 |
| --- | ---: | ---: |
| `gpt-6-astra` | 0.78 | 3.15 |
| `gpt-6.1-sol` | 0.148 | 0.59 |
| `gpt-6.1-terra` | 0.074 | 0.295 |
| `gpt-6-luna` | 0.0078 | 0.0315 |
| `gpt-5.6-sol` | 0.312 | 1.26 |
| `gpt-5.3-codex` | 0.189 | 0.35 |

例如 Sol 短请求为 `(20000 × 2 + 80000 × 0.1 + 10000 × 10) / 1000000 = 0.148`。若没有写入计数，只能确定缓存读取和输出为 `0.108`；剩余 20000 输入不可确定为普通输入，故显示已知小计与缺失提示。

## 已修正的问题

| 问题 | 原行为与影响 | 修正 |
| --- | --- | --- |
| 缺失缓存写入数当零 | 有写入价的模型被误标完整，剩余输入可能错算普通输入 | 保留未知，仅汇总确定分项；无独立写入价、零输入或全缓存输入才推定零写入 |
| 镜像补齐未采用 | 缺失输入占位零或 `inputKnown: false` 阻止有效镜像补齐，漏计费用 | 明确输入优先，保留时间与响应身份，双向合并仅计一次 |
| 日期后缀推断价格 | 任意日期甚至无效日期会被剥除并套用基础模型价 | 仅支持精确型号、已核实官方别名或用户精确覆盖 |
| 重复累计快照基线未推进 | 总计数相同但缓存元数据变完整后，下一次无法正确计算缓存增量 | 不添加响应，只更新累计差分基线 |
