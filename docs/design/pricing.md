# API 等值费用设计

0.1.10 在不调用模型 API 的前提下，将已完成响应的 token 计数按模型转换为美元估算。计价与测速独立：三秒速度窗口、在途估算及曲线重建不改变费用。费用、用量共用同一时间范围、工作区过滤和响应身份去重结果。

## 价格来源及快照

核对日期：2026-10-27。使用 [OpenAI 官方定价](https://developers.openai.com/api/docs/pricing)的 Standard 文本价格。所有历史记录统一按此快照估算，不尝试复原历史价格、实际账户折扣、Codex 订阅费用或服务档位。

单位为美元／百万 token：

| 模型 | 普通输入 | 缓存读取 | 输出 |
| --- | ---: | ---: | ---: |
| `gpt-6-astra` | 10 | 1 | 50 |
| `gpt-6.1-sol` | 2 | 0.1 | 10 |
| `gpt-6.1-terra` | 1 | 0.05 | 5 |
| `gpt-6-luna` | 0.1 | 0.01 | 0.5 |
| `gpt-5.6-sol` | 4 | 0.4 | 20 |
| `gpt-5.3-codex` | 1.75 | 0.175 | 14 |

前五个模型的单次输入超过 272000 token 时，输入及缓存读取乘 2，输出乘 1.5；阈值相等不加价。依据各模型文档，例如 [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)。后者当前为至少延续至 2026-11-21 的促销价格，后续可用配置覆盖。

只匹配精确名称及官方明确确认的别名（当前 `gpt-5.6` 指向 `gpt-5.6-sol`）；不剥除任意日期后缀，也不将未知模型、近似名称或 `-fast` 后缀猜测为已知价格。未经核实的日期型号须单独配置价格。官方价格改变后需更新插件或用户配置；运行中不联网刷新。

## 计数与缺失值

按 [Prompt caching 文档](https://developers.openai.com/api/docs/guides/prompt-caching)，总输入包含缓存命中和缓存写入。普通输入 = 总输入 − 缓存读取 − 单独报告的缓存写入；三项分别乘单价／1000000，最后相加。缓存写入当前不计价并明确显示排除数量，不能按普通输入单价误算。输出包含 reasoning，不另加一次。

现代格式兼容 `cached_input_tokens` 和 `input_tokens_details.cached_tokens`；缓存写入读取 `cache_write_tokens` 及对应详情字段。旧版累计计数的缓存部分也做差分，检查点保存缓存前值；缺失累计缓存时仅接受与本次输入／输出差分匹配的 `last_token_usage` 缓存数。

缓存缺失不等于零；输入计数有效且恰为零时，可确定缓存也为零。缓存数超过输入或拆分不一致时不计算输入费用。无法确定输入总量、且模型存在长上下文加价时，也不猜测输出倍率。界面显示已知费用小计、完整计价响应比例和缺失原因；未知价格显示未计价。金额不逐条舍入，显示精度 2～4 位，小于 0.0001 的正值显示 `<$0.0001`。

缓存写入缺失也不能当作零。对 GPT-5.6／6 等有独立写入价格的模型，若日志只给出总输入和缓存命中数，剩余输入无法区分普通输入与缓存写入；仅计算已确认的缓存读取和输出，显示缺少写入计数。完整零输入、全输入缓存命中、以及官方不设独立写入价格的 `gpt-5.3-codex` 可推定零写入。已知写入数量始终从普通输入中减去并明确排除；本版本仍不估算其 30 分钟／12 小时费用。

同一响应的镜像优先使用明确输入计数，缺失占位零不能挡住另一份日志的有效计数；仍只保留一个响应。旧版累计总量未变化但缓存元数据更新时，只推进差分基线，不产生新的用量或费用。

## 配置与缓存迁移

`codexSpeed.priceOverrides` 为机器级配置，按精确模型名提供三项每百万美元单价，零值有效。负数、非有限数和缺失分项为无效条目，对应模型显示未计价。可选规则示例：

```json
{
  "codexSpeed.priceOverrides": {
    "private-model": {
      "input": 2,
      "cachedInput": 0.1,
      "output": 10,
      "longContext": { "threshold": 272000, "input": 2, "cachedInput": 2, "output": 1.5 }
    }
  }
}
```

已知内置模型继承其长上下文规则，自定义规则可覆盖；未知模型不推断倍率。可选 `cacheWrites` 指定该模型是否有独立缓存写入价；内置模型继承官方规则，未知模型默认 `true`。仅在已经确认没有独立写入价时设置 `false`，不能为隐藏缺失提示而关闭。修改价格只失效查询结果，不重启监控、不清空曲线或用量。

历史缓存继续使用协议 1，每个文件新增 `costVersion: 1`。旧版缓存不丢弃：校验来源身份和断点哈希后，保留已有计数，在原有字节预算内从头重放，按响应 key 原位替换元数据。断点、缓存命中数和模型名一起原子保存；不保存金额和对话正文。源文件删除而无法回填时，旧计数继续保留至过期，费用标为不完整。

## 界面和验证

费用区显示当前范围、总额或已知小计、三项费用、模型及价格来源、完整计价比例和快照日期。英文、简体中文、繁体中文共用同一数据结构；动态日志模型名只使用 `textContent`。保留 Webview 的禁止联网策略。

核心测试覆盖三项算式、多模型、缓存缺失及溢出、未知价格、零价格、长上下文阈值、微小金额不逐条舍入、旧版差分断点、元数据迁移、去重与过滤和改价重算。另在真实扩展宿主和浏览器检查渲染、语言、范围和窄屏布局。

官方规则的逐项核查与独立金额算例见 [计费算法核查记录](pricing-audit.md)。
